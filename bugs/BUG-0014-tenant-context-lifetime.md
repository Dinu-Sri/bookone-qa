# BUG-0014 — Product tenant helper does not bind the callback to tenant context

Provisional P1 runtime compatibility/security-boundary finding. Actual PostgreSQL16, full current schema plus all41 SQL files, product993664b, non-owner NOBYPASSRLS role and actual product postgres-js pool/helpers. The executed helper assertions fail; deployed DB credentials/RLS enforcement and actual leakage are unverified. This is not a claim that staging leaked customer data.

First evidence: [runtime summary](../runs/RUN-2026-10-13T08-28-48-128Z-runtime.json), [CI1](https://github.com/Dinu-Sri/bookone-qa/actions/runs/38369449028), QA implementatione0382ae3 / tested PR merge01b129d7. RT-001 own-tenant transaction/RLS positive control and RT-003 separate-connection own/foreign read/write checks pass. RT-002 product `withTenantContext` callback and RT-004 tenant switching/exception cleanup fail. Exact numeric diagnostics are added in the follow-up run; do not infer returned row values from status-only first evidence.

Source: `packages/db/src/helpers.ts` uses `set_config('app.current_tenant_id', tenantId, true)` on `pgClient()` as a standalone query, then invokes arbitrary callback DB calls. `true` is transaction-local; an autocommit query ends its transaction before callback work. The callback also uses a pool without pinning the same connection/transaction. `clearTenantContext` has the same standalone pattern. Auth permission loader queries are another area to review: they do not automatically bind a tenant-scoped transaction.

Repair requirements: make tenant state, permission loading and queries run on the same explicitly scoped connection/transaction for the complete operation, including nested helpers and business transactions. Fail closed for absent/invalid tenant context and always clear/rollback safely; avoid session settings leaking on reused connections. Confirm deployed runtime role is not table owner/superuser/BYPASSRLS rather than assuming policies enforce it. Keep correct tenant predicates/composite ownership checks even with RLS.

Acceptance: both helper tests pass through an actual non-owner role with positive own rows and real foreign rows; alternate/interleave tenants and thrown callbacks on multiple pooled connections; actual login/permission loading and commercial/reversal actions under the intended runtime role. Owner-mode commercial passes are explicitly separate evidence. No production credential changes or staging resets were performed by QA.
