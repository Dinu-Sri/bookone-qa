# Portable synthetic bank parser fixtures

The four inherited optional-fixture assertions now have fabricated inputs generated by scripts/fixtures/bank.mjs into ignored .local/synthetic-bank-fixtures.24Sampath-style DR/CR rows and64HNB-style debit/credit rows include the exact independently declared sign/amount examples in the original tests. No real statement, account number, customer, filename or bank export was copied. These are generic bank-style parser controls, not certification of every genuine bank export layout.

`pnpm test:unit` verifies the product pin, creates fixtures, sets QA_FIXTURE_SAMPATH/HNB only for its child and runs unchanged assertions. Local first result98passed0skipped. Original unit IDs/titles/expectations are unchanged; earlier skip evidence stays immutable. The old optional metadata means tests can still skip when deliberately invoked without these inputs; production acceptance may not count such skips as passes.

Campaign-v2 prepares the same inputs before stages and records bankFixtureHash in the fingerprint. During the run it rechecks actual workbook bytes along with QA/product/content identities. Changed/missing fixture bytes invalidate continuation. Files and raw results stay private and are never uploaded; source generator and sanitized hashes/outcomes are public. A changed fixture source/hash requires a fresh run, not a rewritten historical pass.

The fixture version, rows, independent opening/net/closing values and byte hashes are in the private generated manifest. Workbook metadata dates are fixed for replay. A real-bank layout or parser issue still requires a separate portable redacted/synthetic reproduction. Actual bank reconciliation/import commit, permissions, file storage and browser workflows remain independent acceptance layers.
